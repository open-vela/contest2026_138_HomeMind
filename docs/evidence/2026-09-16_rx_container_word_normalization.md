## 2. 硬事实

### 2.1 现场流的字节结构（`_raw_peek.py`，rms=800 的段）

```
word 4000 | 00270000 | 低半=0 | 高半=39
word 4001 | 00270000 | 低半=0 | 高半=39
word 4002 | ffe80000 | 低半=0 | 高半=-24
```

字节流 = `27 00 00 00 27 00 00 00 e8 ff 00 00 e8 ff 00 00 …`
⇒ **一个 16 位样点占 8 字节**：2× 来自"半字承载 / 另半字填 0"，2× 来自**成对重复**。

### 2.2 两个独立的刚性判据

- 每个 32 位字里**恰好一个**非零半字 = **96.7%**；**两半皆非零 = 0.0%**。
- 还原流 `S`（每字取非零半）的**游程直方图：长度 2 占 93.0%**，且几乎只有偶数长度
  （2/4/6/8/10）。自然语音的游程几乎全是 1 —— 对照 `record/pcm/pos01.pcm` 是 **96.6%**。
  ⇒ 结构性重复，不是信号。

### 2.3 真实样点率 ≈ 4000 Hz（三条独立证据）

1. **墙钟**：`[STRM]` 160000 B / ~5.0 s ⇒ 8000 个容器字/s；每样点占 2 字 ⇒ 4000/s。
2. **内容带边**（`_bw_calib.py` 砖墙低通扫描）：带边落在 1.5–2 kHz 之间。
3. **解码行为**：去重复流声明 8000 时 VAD 全丢，4000/6000 才出文本。

> 注意：`[STRM] eff_rate ≈ 15570` 是 **int16 投递率**，不是麦克风声学采样率。
> 别再把 16000 当成采样率写进文档。

### 2.4 关键校准（防止把 whisper 的偏好当速率）

whisper 的"最佳声明速率"在 `S`(8000/s) 上是 10000–12000、在 `D`(4000/s) 上是
4000–6000 —— **两者都 = 样本率 ×1.5**，那是模型偏好。
决定性校准：把同一段做 2 kHz 低通再送，`4000 Hz` 下得分与**无低通完全相同（83.3%）**，
1.5 kHz 才崩到 33% ⇒ **2 kHz 带宽不构成 ASR 障碍**，4000 Hz 结论成立。

## 3. 主因：采集路径把"容器字"当 PCM 上传

- RX 路径是**纯 DMA 直通**：`i2s_rxdma_setup()` 直接把 DMA 目标设为 `apb->samp`，
  驱动**不做任何字→样点转换**（与 ESP-IDF 在 ISR 里按 `bits_per_sample` 拆包不同）。
- `hm_audio_stream_session()` 里一句**整块 `memcpy`** 就把原始流交给上层，
  再由 `hm_voice_utterance_roundtrip()` 按 16000 声明上传。

用服务端 `local_asr` 做裁判（字符级 LCS）：

| 送法 | 声明速率 | 平均相似度 |
|---|---|---|
| `rawX`（现状） | 16000 | **3.6%** |
| `D` 去重复 + 线性插值 ×2 | 8000 | **47.6%** |
| `D` + 线性 ×4 | 16000 | 48.4% |
| `D` + ZOH ×4（零阶保持） | 16000 | 34.9%（镜像有害） |
| `S`（只取非零半，不去重） | 8000 | 31.0% |

⇒ **糊的主因不是采样率错配，是把容器字当 16 位 PCM。**

## 4. 修复

`transfer/_patch_rx_normalize.py`（幂等，标记 `g_hm_rx_normalize`）改 overlay
`firmware/ai_agent_overlay/src/channels/nsh_commands.c`：把整块 `memcpy` 换成
**逐字流式归一化**

1. 每个 32 位字取非零半字 → 一个样点（两半皆零给 0）
2. 吃掉与上一个保留样点原值相同的重复（成对，只吃一次 —— 与离线 greedy 对齐）
3. 线性插值 ×2：`y[2n]=x[n]`、`y[2n+1]=(x[n]+x[n+1])/2`（1 样点前瞻）

输出 **8000 Hz**，落在云端 `/v1/voice/utterance` 只收的 8000..48000 区间内。
状态变量是**函数局部量**，每次会话自动重置；`g_hm_mic_rate_hz` 按写入样点计数，
因此自动变成 ≈8000，与云端区间自洽。新增 `[RXNORM]` 观测行。

## 6. 被否掉的假设（别再回头）

- **"时钟源选错"**：`I2S_RX_CLK_SEL` 写入 `2` = **CLK160**（芯片头文件：
  0=XTAL / 1=APLL / 2=CLK160 / 3=MCLK_in），与 `sclk = I2S_LL_BASE_CLK = 160 MHz`
  一致 ⇒ 假设否定。
- **"TOT_CHAN 是帧宽杠杆"**：`i2sknob … totchan ∈ {-1,0,1,3}` 扫描，
  `eff_rate` 几乎不动（16000 / 15353 / 15276 / 15515）⇒ 无影响。
- 4× 慢（4000 Hz vs 请求 16000）的成因**仍未定**：当前寄存器真值为
  `TDM_EN=1`、`TOT_CHAN=0`、`dw=16 slot=2`、`BCK_DIV=7`、`CLKM_DIV=39`。
