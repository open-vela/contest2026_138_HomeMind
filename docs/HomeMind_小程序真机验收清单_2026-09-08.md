## 1. A1 首次登录（wx.login → 换 token）

操作：手机扫码进入小程序 → 进"设置"页看登录状态卡片 / 进"设备"页触发自动登录。

| 项 | 期望 |
| --- | --- |
| `wx.login` 拿到 code | vConsole 无 `no code` |
| `POST /v1/auth/wechat/login` | 200，返回 `access_token`、`user_id` |
| Storage | 出现 `accessToken`、`userId`；`refreshToken` 保持不存在 |
| UI | 设置页显示已登录 |

失败速查：

- `invalid code` → 云端 `.env` 的 AppID/AppSecret 与小程序 AppID 不一致，或 code 被复用（code 5 分钟内一次性）。
- 一直 401 → 云端 JWT 密钥与签发时不一致；小程序侧已有"401 强制重登一次"自愈，若仍 401 说明是服务端问题。
- 静默无反应 → 检查是否旧 Storage 短路，回到 0.3。

## 2. A2 设备列表与绑定

| 项 | 期望 |
| --- | --- |
| `GET /v1/devices` | 200，返回 `esp32s3-eye` |
| 自动绑定 | 设备页无需手填即可绑定 |
| 米家实体行 | 自动渲染"多功能房吸顶灯"（由网关上报的 friendly_name 同步），带当前状态 |

失败速查：实体行不显示 → 网关离线或未上报 `mihome_entities`；手填实体 ID 输入仅作网关离线兜底，出现即说明同步链路断了。

## 3. A3 / A4 单次控制与状态回读

1. 点"开" → 观察命令状态 `queued → acked → done`，灯**物理点亮**，UI 显示"已开启（网关回读确认）"。
2. 点"查状态" → 与 HA 中该实体状态一致。
3. 点"关" → 同上，灯物理熄灭。

判定：三态齐全且物理动作与 UI 一致才算通过。**只到 `acked` 不算**——`done` 才是网关回读确认。

## 4. A5 稳定性回归（开/关各 10 次）

记录每次：序号、方向、queued→acked 耗时、acked→done 耗时、物理是否动作、UI 文案。

| 指标 | 通过线 |
| --- | --- |
| 成功率 | 20/20 |
| done 超时（TTL 过期） | 0 次 |
| 物理动作与 UI 不一致 | 0 次 |

若出现 1～2 次 `expired`：属 HA 状态滞后，网关侧已有 3 秒确认窗口；连续失败则停手，先查家庭 Mosquitto 与网关 systemd 状态，别硬刷。

## 5. A6 断线重连

1. 手机开飞行模式 10 秒 → 关飞行模式。
2. 观察：WSS 是否自动重连；命令最终态是否靠轮询补回；页面是否给出提示而非卡在"执行中"。

## 6. A7 弱网

用路由器限速或开发者工具弱网模拟，重复一次开/关。期望：超时后有明确失败 toast，不白屏、不静默、不重复下发（防重入只在 `done/expired` 解除）。

## 7. A8 失败提示

在设置页把服务器地址临时改成另一个无效 https 域名 → 期望：请求失败时页面显示"服务不可用"类提示，且不会留下"假成功"。测完改回 `https://hfy-ai.cloud`。

## 8. A9 冷启动与后台切回

杀掉小程序进程重进 → 期望 token 仍可用、WSS 重连、设备状态刷新。切后台 5 分钟再回来同测。
