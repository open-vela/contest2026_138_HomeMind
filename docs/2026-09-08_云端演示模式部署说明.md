# 云端"演示模式"部署说明（2026-09-08）

## 一、为什么要改：一个已经存在的安全问题

`backend/api/app/routers/auth.py:36-47`：**任何用户用微信首次登录，都会自动绑定 `esp32s3-eye`**。
配合 `ALLOWED_ACTIONS` 里含 `mihome.set_power`，等于——

> 任何能打开这个小程序的人（包括提审审核员、拿到体验版二维码的人），
> 都能对你的家庭网关下发开关命令，控制**多功能房吸顶灯这台真实电器**。

当前小程序还没正式发布，所以风险还没暴露；一旦进审核流程或扩散体验二维码，就会变成一个真实的家居安全问题。

演示模式的方向是**收紧而非放开**：审核员照样能看到设备、点 LED、查状态（有东西可审），但碰不到真实灯具。

## 二、改动清单（已改，本地仓库）

| 文件 | 改动 |
| --- | --- |
| `backend/api/app/config.py` | 新增 `DEMO_MODE`、`TRUSTED_USER_IDS`、`DEMO_ALLOWED_ACTIONS` 三项配置，默认关闭、默认不含 `mihome.set_power` |
| `backend/api/app/routers/commands.py` | 演示模式下，演示设备对非受信任用户只放行 `DEMO_ALLOWED_ACTIONS`，其余返回 **403** 并记日志 |
| `backend/docker-compose.yml` | api 服务补上三个环境变量（默认值安全，靠云端 `.env` 覆盖） |
| `miniprogram/pages/devices/devices.js` | 米家动作收到 403 时提示"演示模式：此操作不可用"，不再回显一长串英文 detail |

已通过检查：`py_compile` 编译通过、`node --check` 通过、`app.json`/`project.config.json`/`sitemap.json` JSON 解析通过。

## 三、部署步骤（云主机 `/home/ubuntu/homemind/backend`）

### 1. 先拿到你自己的 user_id

最简单：微信开发者工具 → 调试器 → Storage 面板 → 看 `userId` 的值（登录后才有）。

或者在云主机查（DB 属主是 root，要 sudo）：

```bash
sudo sqlite3 /home/ubuntu/homemind/backend/api/data/homemind.db \
  "SELECT user_id, openid FROM users;"
```

### 2. 改云端 `.env`

```bash
cd /home/ubuntu/homemind/backend
cp .env .env.bak-$(date +%Y%m%d-%H%M%S)     # 先备份
vi .env
```

追加（`<你的userId>` 换成上一步拿到的值）：

```
DEMO_MODE=true
TRUSTED_USER_IDS=<你的userId>
DEMO_ALLOWED_ACTIONS=led.on,led.off,device.info,mihome.get_state
```

注意：`DEMO_ALLOWED_ACTIONS` **不要**加 `mihome.set_power`，那正是要挡住的动作。

### 3. 重建并重启 api（只传文件无效，必须 build）

```bash
sg docker -c 'docker compose build api'
sg docker -c 'docker compose up -d --force-recreate api'
```

### 4. 验证

```bash
# 改动确实进了镜像
sg docker -c "docker exec backend-api-1 grep -c 'DEMO_ALLOWED_ACTIONS' /app/app/config.py"
# 健康检查
curl -s https://hfy-ai.cloud/v1/health
```

功能验证：

| 账号 | 动作 | 期望 |
| --- | --- | --- |
| 你的账号（受信任） | `mihome.set_power` | 正常执行，灯物理动作 |
| 另一个微信账号 | `mihome.set_power` | 403，小程序提示"演示模式：此操作不可用" |
| 另一个微信账号 | `led.on` / `mihome.get_state` | 正常执行 |

## 四、回滚

```bash
# 方式一：只关演示模式（保留代码）
sed -i 's/^DEMO_MODE=true/DEMO_MODE=false/' .env
sg docker -c 'docker compose up -d --force-recreate api'

# 方式二：连带 .env 一起回退
cp .env.bak-<时间戳> .env
sg docker -c 'docker compose up -d --force-recreate api'
```

## 五、还没解决的事

- 演示模式下设备**状态仍然对所有登录用户可见**（能看到灯是开是关）。只是不能操作。若连状态也要隐藏，需要改 `routers/devices.py` 的 `list_devices`，按用户过滤 `mihome_entities`。
- 自动绑定本身没改。更彻底的做法是关掉 `auth.py` 的自动绑定、改为显式绑定，但那会让审核员看到空页面，与"让审核有东西可审"冲突，暂不动。
- 本次改动只在本地仓库，**尚未部署到云端**（需要云主机 SSH 凭据）。
