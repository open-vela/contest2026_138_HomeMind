## 二、发现并已修复的问题：审核员视角的"死按钮"

**问题**：此前演示模式下，陌生人（含审核员）在米家设备行能看到「开/关」按钮，点击后收到
403「演示模式：此操作不可用」。审核员会把可点但报错的按钮判为**功能不可用**，这是最可能
的驳回原因。

**修复（2026-09-11 已部署云端并验证）**：

- 云端 `GET /v1/devices` 每个设备新增 `allowed_actions` 字段，按用户判定
  （`routers/devices.py::allowed_actions()`，执行侧 `commands.py` 仍二次校验，权限不以客户端为准）；
- 前端 `devices.js` 透传 `allowed_actions` → `can_led`/`can_mihome`（字段缺失时按只读降级，fail-closed）；
- 前端 `devices.wxml`：无 `can_mihome` 时只渲染「查状态」，并显示
  「当前为访客模式：可查看设备与实时状态；控制权限由设备所有者授予」；
  手动输入实体 ID 的兜底输入框同样仅对可控制账号显示；
- HTTP 层实测（容器内签发真实 token）：

```
陌生人(审核员视角) | esp32s3-eye | allowed_actions = ['device.info','led.off','led.on','mihome.get_state']
   can_mihome(前端推导): False   → 不渲染开/关按钮
本人(白名单)      | esp32s3-eye | allowed_actions = [...,'mihome.set_power']
   can_mihome(前端推导): True    → 完整控制
```

审核员现在的体验：登录 → 看到设备在线 → 板载 LED 可开关（真实反馈）→ 米家实体可查状态 →
无任何报错死按钮。

## 三、非阻塞观察项（可不改）

1. **设置页"API 服务器"输入框**：允许用户改服务器地址。审核一般不深究，但如求稳可在提审版隐藏。
2. **仪表盘 4 项"未接入"**（温湿度/光照/噪声）+ 告警未接入：已诚实标注，配合类目"信息查询"
   反而说得通；若被驳回可考虑临时隐藏仪表盘 tab。
3. emoji 图标（📊📱📅 等）：能正常渲染，非违规，仅观感一般。
4. `settings.js` 中 `onSettingChange` 为无引用死代码，可删可留。
5. 添加设备弹窗要求手填设备 ID：审核员已有自动绑定设备，通常不会用到；如求稳可隐藏入口。
