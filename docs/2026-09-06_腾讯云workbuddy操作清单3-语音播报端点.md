# 腾讯云操作清单（三）：媒体端点 + 语音播报 — 交 workbuddy 执行（现在可以执行）

背景：HomeMind 语音/视觉链路最终方案为"设备采集 → 云端转码 → MiMo 全模态 → 结果回设备 / 小爱音箱播报"。云端新增 `/v1/media/*` 三个端点（代码已写好，见下方文件清单）。前两份清单的操作（ALLOWED_ACTIONS、实体同步）已由 workbuddy 完成。

## 端点行为摘要（详见 media.py 源码注释）

- 鉴权：`Authorization: Bearer MEDIA_TOKEN`（设备级共享令牌，与用户 JWT 隔离）；未配置 MEDIA_TOKEN 或 MIMO_API_KEY 时端点 503 fail-closed；
- `POST /v1/media/frame?w=320&h=240&swap=1&q=<提示词>`：body 为 RGB565 裸帧 → 云端转 JPEG → 调 MiMo `mimo-v2.5` 图像理解 → `{"text": 描述}`；限流 10 次/分；
- `POST /v1/media/audio?rate=16000`：body 为 16bit 单声道 PCM → 云端包 WAV → MiMo 音频理解转写 → `{"text": 文本}`；限流 10 次/分；
- `POST /v1/media/announce` `{"device_id","text"}` → MQTT `device/<id>/speak` → 家庭网关（speak 动作已上线并实测播报成功）→ 小爱音箱；限流 6 次/分。

## 操作步骤

```bash
ssh <腾讯云主机>; cd /home/ubuntu/homemind/backend
# 0) 备份 + 生成密钥
cp api/app/main.py api/app/main.py.live.bak.$(date +%Y%m%d_%H%M%S)
cp docker-compose.yml docker-compose.yml.live.bak.$(date +%Y%m%d_%H%M%S)
echo "MEDIA_TOKEN=$(openssl rand -hex 24)" >> .env
echo "MIMO_API_KEY=<HomeMind 另行提供的小米 MiMo key>" >> .env
echo "MIMO_MODEL=mimo-v2.5" >> .env
chmod 600 .env
# 1) 覆盖 4 个文件（仓库 -> 云端同路径）
# 2) 语法检查
python3 -B -m py_compile api/app/main.py api/app/routers/media.py
# 3) 重建（requirements 变了必须 build）
docker compose build api && docker compose up -d --force-recreate api && sleep 8 && docker compose ps
# 4) 验收
curl -s https://hfy-ai.cloud/v1/health
# 无 token 应 401/403；带错误 token 同样拒绝：
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://hfy-ai.cloud/v1/media/announce \
  -H 'Authorization: Bearer wrong' -H 'content-type: application/json' \
  -d '{"device_id":"esp32s3-eye","text":"x"}'
# （HomeMind 拿到 MEDIA_TOKEN 后会从设备/网关侧做端到端验收，届时音箱应播报）
```

## 密钥交接

- `MEDIA_TOKEN`：你生成后把值通过安全渠道给 HomeMind（写入设备 flash 与网关 .env 用）；
- `MIMO_API_KEY`：HomeMind 提供（用户的小米 MiMo key），只进云端 `.env`，不进日志/提交物。

## 红线（同前两份清单）

- 不动其他 `.env` 键、MQTT_PASS、nginx/mqtt 容器；不新增公网端口；
- `MEDIA_TOKEN`/`MIMO_API_KEY` 值不回显日志；shell 历史不留 token 明文；
- 失败回滚：恢复备份文件 + `docker compose build api && up -d --force-recreate api`。
