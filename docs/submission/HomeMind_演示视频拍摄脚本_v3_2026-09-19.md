## 附录 A：为什么端侧唤醒不拍（更新版事实）

### A1. 09-18 上午的旧结论（已作废）

2026-09-18 上午曾测得板载麦上传的 PCM「逐 100ms 为平线、峰值 32–40」，据此判断为数字静音。
**该结论已于 09-18 13:20 被推翻。**

### A2. 09-18 13:20 实测（现行结论）

以小爱音箱作声源，板载麦实测 PCM：

| 指标 | 实测值 |
|---|---|
| 峰值 | 7433 – 18432 |
| RMS | ≈ 930（小爱 0.5 音量）；近距离说话可 >200 |
| 非零率 | ≈ 95% |

⇒ **采集链路是通的**。端到端也验证过：板端真实 PCM 回放 → ASR 听成「打开客厅的灯」近似音 → `device.control` → `led.on` **done** + 待办 + 播报。

### A3. 仍然不达标的部分

| 项 | 状态 |
|---|---|
| 端侧**指定词 KWS**（逻辑回归，8 维时域特征） | ❌ 主机域正负样本完全分离（POS 0.97–0.99 / NEG 0.001–0.048），但**实机 live 得分恒为 0**。根因是训练域与实机域特征偏移（训练样本过零率均值≈0.12，实机≈0.48），权重把特征打穿 |
| 端侧 **24/7 常驻监听** | ⚠️ 「缓冲分配缺失 `AUDIOIOC_GETBUFFERINFO`」的缺陷已定位并修复（串口刷屏 197 行/s → 0），但随后阻塞在采音启动路径，**未闭环** |
| ASR 对短指令近音 | ⚠️ 仍会听糊（「打开客厅」→「打开口气」），已加近音容错规则 |

⇒ 结论：**端侧唤醒与常驻监听是未来工作**；当前演示的唤醒词校验放在家庭私有云，是真实可运行、可复现的路径。

## 附录 C：板载 LED 命令 "expired during execution" 的根因与修法

### 症状

```
收到命令 d0dcfbed… -> led.off
ERROR 执行命令 d0dcfbed… 失败：command expired during execution    ← 30s TTL 到期
```

### 根因：网关握着一个**作废的串口 fd**

USB 一旦重新枚举（插拔 / 板子复位 / 供电抖动），`ttyACM0` 是**新的 tty 实例**，
网关旧的 fd 指向已销毁的那一个 ⇒ 写进去啥也到不了板子。
网关**没有**失联自愈逻辑，且 `SerialExecutor.open()` **从不校验是否真的看到 `vela>`**，照样打「串口会话已就绪」。

### 修法（一条命令）

```sh
echo 123456 | sudo -S systemctl restart homemind-gateway
```

**副作用**：重开串口会复位板子，NSH 约 20–30 秒可用（拍片不需要板子联网，无影响）。

## 附录 D：目标灯在 HA 里 `unavailable` 怎么办

`unavailable` 意味着 **HA / 米家在云端根本看不到这盏灯**，与 HomeMind 无关。
先查电源：墙面开关是否被关、所在回路是否断电、灯的 Wi-Fi/BLE 是否掉线。

### 备选灯：同型号「客厅大灯」

`light.leishi_cn_861832529_eps127_s_2_light`（雷士 eps127，与目标灯同型号）。

一键换过去（改 `.env` 三行 + 重启 API）：

```sh
cd /home/hfy/homemind-backend
sed -i 's|^HA_WATCH_ENTITIES=.*|HA_WATCH_ENTITIES=light.leishi_cn_861832529_eps127_s_2_light,media_player.xiaomi_cn_2085562629_lx06|' .env
sed -i 's|^HA_BEDTIME_LIGHT=.*|HA_BEDTIME_LIGHT=light.leishi_cn_861832529_eps127_s_2_light|' .env
sed -i 's|^HA_BEDTIME_VOICE_CMD=.*|HA_BEDTIME_VOICE_CMD=关闭客厅大灯|' .env
echo 123456 | sudo -S systemctl restart homemind-api
```

（证据墙的 `light` 卡片读的是**硬编码**常量，换灯后要同步改
`/home/hfy/homemind-livefeed/livefeed.py` 的 `LIGHT` 常量并重启 `homemind-livefeed`。）
