## 提交计划分类与时间窗口

### 必做（提交前）

- 官方 PR 合入阻塞需跟进；归集完成后必须从官方分支核对最终文件和 commit，不能把 open PR 或 fork 推送当成提交完成。
- 从 Ubuntu 权威现场归集源码、驱动补丁、配置、构建工具、模型、BIN/ELF/manifest 及完整哈希，并完成干净构建。
- 对最终选定闭环做最小演示回归；完成正式报告、AI 开发说明、视频和硬件多角度照片。
- 将现有 14 份 JSONL / 2016 events 与 manifest 纳入最终源码树，保留历史日期和校验结果；补开发 `SKILL.md` 与 `LICENSE` 以及第三方归属。
- 生成、解压并核验提交包，保存上传回执和最终线上版本校验。

### 条件必做（纳入报告或视频时）

- 视觉、能量 VAD/连续音频、米家灯光、客户端链路、断网/恢复等展示项，须按最终版本复测，记录实际条件、次数、成功/失败和耗时；误报/漏报按实际样本统计，P50/P95和峰值内存仅在实测可取得时填写。
- 当前吸顶灯开关各 10 次、视觉 20 正/20 负、语音各环境至少 20 次，以及连续运行 4 小时等项目自定目标，只有在作为成果声明时才是本轮必须补齐的量化证据；未纳入时写清限制，不得用估计值填充。

### 赛后后置

- 指定词 KWS、严格私有化、完整睡前语义任务、跨端日程同步，以及家庭迁移/隐私闭环继续标记为未实现；它们不阻塞本次提交计划。
- 海报和答辩 PPT 留到入围或线下展示阶段。
